# 苦手な動きと対策

補間がうまくいかない動きの一覧と、その根本の原因、対策の状況です。数字は合成映像・写真を動かした映像での PSNR（dB、t = 1/8〜7/8 の平均、高いほど正確）で、場面の詳細は README の比較表にあります。対策のたびに更新します。

## 補間しないほうがよい場面

急な変化そのものが演出になっている場面（一瞬の大きな動き、画面の揺れ、フラッシュ）は、完璧に補間できてもなめらかになったぶん勢いが弱まります。設定「演出を優先」で、これらを検出した組は補間せず元のタイミングで表示できます（0.5.9、既定はオフ）。判定は組ごとの動きの統計を前の組と比べて GPU 上で行います：動きの大きい画素の割合と平均の大きさが前の組より急に増えた（ツメ・スミア、続く間も含む）、画面全体の動きの向きが組ごとに反転する（揺れ）、明るさが急に変わる（フラッシュ。ゆっくりしたフェードは対象外）。合成した動き（パン、7.5%/フレームの速いパン、歩く物体、フェード）では検出されず、瞬間移動・揺れ・フラッシュでは検出されることを確認済み。

## 根本の原因

### 空間：動きを局所的な見た目の一致だけで決めている

繰り返し模様では、本物の動きと 1 周期ずれた偽の動きが、2 枚のフレームの上ではまったく同じに見えます（どちらで変形しても前後のフレームが一致する）。RIFE もブロックマッチングも偽の動きを選ぶことがあり、変形の誤差では見分けられません。見分けるには、模様のない周りの部分（建物の縁、地面、人物）の動きと揃っているかという、空間的な文脈が必要です。

一定の速さの動きでは、前のフレームの組でも同じように 1 周期ずれるので、時間方向の手がかりだけでは解決しません。

### 時間：フレームの組ごとに、2 枚だけから毎回ゼロから推定している

実際の映像は連続していて、前の組の動きは次の組の動きのよい予測になります。特に大きな動きでは、予測を出発点にすれば、残りの小さな動きだけを推定すれば済みます。今はこの情報を使っていません（ブロックマッチングの最上位の探索で前の組のベクトルを候補にしているだけ）。前の組の動きを RIFE の出発点にする実験では、当たる場面の改善は大きい一方、前の組の誤りも引き継ぐため、どちらを使うかの判定が鍵になります（実験の記録を参照）。

### 拡大縮小：平行移動しか探していない

ブロックマッチングは平行移動の候補だけを探します。RIFE も、近づいてくる物体のように局所的に拡大する動きを苦手とします。

### 1 画素 1 動き：1 つの画素に 1 つの動きしか持てない

半透明の重なり（雨の向こうの景色）や、動きではない見た目の変化（閃光、エフェクト）は、1 つの動きでは説明できません。今は無理に動きとして解釈して崩れるか、ほとんど補間されない（単純ブレンドと同じ）状態です。どの動きでも説明できない画素では、壊れた変形の代わりにクロスフェードにするのが、少なくとも素直な振る舞いです。

### 学習データ：使い分けのモデルを合成映像だけで当てはめている

AI と従来方式の使い分けは、合成映像に当てはめたモデルで決めています。合成映像にない種類の動き（形の変わる動き）では判断を誤ることがあります。実際の動画のデータで当てはめ直すのが本筋です（利用が許されている動画で集める）。

### 補間の混合：輪郭の硬い絵を前後のフレームの混合でぼかす

ドット絵は、半端な位置に描かれることがなく輪郭が硬いので、2 枚のフレームの混合や画素の補間でぼけます。

## 実験の記録

本実装の前に、「理想的に働いたらどれだけ良くなるか」を測った結果です（16 画素四方のブロックごとに、正解を見て最善の候補を選んだ場合を上限とする）。

| 試したこと | 結果 | 採否 |
|---|---|---|
| RIFE のアンサンブル（入れ替えた組でも推論して平均） | 実際のエンジンで 28 種類の平均 +0.13 dB、アニメ +0.96、フェード +0.66、パン +0.48。最大の低下は −0.21（ドット絵） | 採用（既定でオン） |
| 動きで説明できない場所をクロスフェードに | 上限でも平均 +0.15 dB。雨 +0.9、風の草 +0.5 だが、衝撃波などのエフェクトは改善しない | 見送り |
| 3 枚目のフレームで候補を検証（等速を仮定） | 平均 +0.24 dB だがほぼ 1 場面（RPG）だけ。アニメ −0.65 など場面によって悪化 | 見送り |
| 使い分けの重みを鋭く（中間の混合を減らす） | すべての強さで悪化 | 見送り |
| 1/4 の解像度の RIFE も候補に | 平均 +0.09 dB（アニメ +0.36）に対して GPU 負荷が増える | 見送り |
| 画面全体の動き（カメラの動き）を候補に | ブロック単位の上限で平均 +0.4 dB 程度 | 見送り |
| 前の組の動きを出発点に推論（等速で外挿し、RIFE の最初の段に変形済みの入力を渡す） | 合っている場面では大きく改善（パン +12.9、ズーム +3.9、アニメ +2.2 dB）。前の組の推定が 1 周期ずれている繰り返し模様では誤りを引き継ぐ（ドット絵 −4.1、高速移動 −1.9）。28 種類の平均は変わらず（アンサンブル同士で 33.28 → 33.28）。画素ごとに変形の一致で選ぶと +0.34 dB だが推論が 2 倍、上限（16 画素四方で最善）は +1.39 dB | 見送り（選び方が課題。同じ費用の左右反転のアンサンブルと同程度） |
| 実際のアニメの映像（トレーラー 8 本、128 組）で検証。絵を 1 枚抜き、前後から補間して本物と比べる | 今の既定（ハイブリッド＋アンサンブル）27.8 dB、AI のみ 27.3 dB、単純ブレンド 26.4 dB。合成映像で決めた工夫は実際のアニメでも効いている。大きく崩れるのは炎・電撃・光の明滅・毎コマ描き直すエフェクト線など、動きではない作画 | — |
| 動きで説明できない場所をクロスフェードに（実際のアニメで学習） | 16 画素四方で良いほうを選ぶ上限は +1.6 dB だが、学習すると画面全体を 4 割ほどぼかす判定になり、合成映像で −3.2 dB。合成映像も入れて学習すると、どこもクロスフェードにしない判定になる。上限の大半は、ぼかすほど点が上がる測り方のくせ（2 コマ打ちのキャラクターと毎コマ動く背景が混ざる場面では、本物の中間の絵が定まらない）によるもの | 見送り |
| 半分の解像度の動きを出発点に、元の解像度で推論し直す（2 段構え） | 縞模様の高速移動 +2.3、車輪 +2.3 dB だが字幕 −4.1。今の候補（元・半分の解像度）に 3 つ目として加えた上限の上乗せは、合成映像 +0.31、実際のアニメ（動きの大きい 48 組）+0.14 dB。推論が約 4 割増えるのに見合わない。自分の結果を出発点にもう一度推論する案も同程度（迫る動き +0.9） | 見送り |
| 動きを広い範囲の中央値で置き換えた候補（繰り返し模様の取り違えを周りの動きで上書き） | ビルの窓のあるアニメで上限 +1.2 dB だが、平均の上乗せは合成映像 +0.14、実際のアニメ +0.15〜0.24 dB。縞模様の箱は箱全体が取り違えられていて直らない | 見送り |
| 迫る動き：前後どちらの絵から取るかを正しく選んだ場合 | 上限 +0.5 dB（16 画素四方）。動きの推定そのものが外れていて、選び方では直らない | — |
| 別の版の RIFE を専門家として加える（MoE の考え方） | 4.26 は 4.25 と得意・不得意がずれる（ビルの窓のアニメ +2.8、走る人物 −4.3 dB）。足すと推論が 2 倍。重い推論を必要な場面だけ動かす振り分けは、手軽な手がかり（動きの大きさ、解像度間の食い違い）では効く場面を予測できなかった（相関 0.14 以下） | 見送り |
| アンサンブルの 2 回目を 4.26 に（推論の回数は同じ） | 実際のエンジンで合成映像 +0.10 dB（フェード +1.2、ドット絵 +0.5、最悪 −0.16）、実際のアニメ 128 組 +0.01 dB。処理は約 1 割増 | 設定として追加（既定はオフ） |
| 合成映像で RIFE 4.25 を追加学習（CPU での予備の学習、3000 回 × 4 組） | AI 単体では、テスト用の合成映像（作り方が学習データと別）+1.0 dB（フェード +8.7、ズーム +4.7、車輪 +4.7、アニメ +3.4）、実際のアニメ 48 組 +0.4 dB。エンジンに入れると合成映像 +0.23、実際のアニメ ±0。走る人物・VTuber 風など形が変わる動きや小さな動きで悪化することがあり、学習データの調整で入れ替わる。GPU での本番の学習（本物の映像も混ぜる）を training/ に用意 | 検証中 |
| 写真を動かした映像も使い分けの学習に加える | 風の草は改善するが高速移動が −0.5 dB、平均は変わらず | 見送り（アンサンブル用のモデルでは 28 種類で学習） |

ここまでで分かったこと：今ある候補（RIFE・半分の解像度の RIFE・ブロックマッチング）から最善を選べたとしても、改善の余地は平均 1.4 dB 程度です。苦手な場面の多くでは、どの候補も動きを正しく捉えていません。根本の対策は、選び方よりも動きの推定そのものを良くすることで、アンサンブルはその最初の一歩です。

## 進め方

1. 時間と空間：前の組の動きを予測として使う／周りと揃っているかを使う。まず、連続した 3 枚以上のフレームで評価できるようにする
2. 1 画素 1 動き：動きで説明できない場所はクロスフェードにする
3. 拡大縮小 → 学習データ → 補間の混合

各対策は、本実装の前に「理想的に働いたらどれだけ良くなるか」を測り、効果のあるものから実装します。
