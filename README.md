# NuruNuru Frames AI

YouTube とニコニコ動画を **ブラウザの中で AI（RIFE）を使って** フレーム補間し、ディスプレイのリフレッシュレート（例: 144Hz / 180Hz）でぬるぬる再生する拡張機能です。
[NuruNuru Frames](https://github.com/wahahahaha1/nurunuru-frames)（ブロックマッチング版）の別版で、動き推定を AI の補間モデル **RIFE v4.6** に置き換えています。

- RIFE の推論を WebGPU のコンピュートシェーダーで自前実装しています。onnxruntime などの外部ランタイムは使いません（同梱するのはモデルの重み約 10MB だけです）
- 推論は **ソースの 2 フレームにつき 1 回**（中間時刻 t=0.5）だけ行い、任意の時刻 t のフレームは、その結果を使って軽いシェーダーで作ります。出力が 144fps でも 180fps でも推論回数は増えません
- 1 回の推論を複数の表示フレームに分けて GPU に投入するので、推論中も画面の更新が止まりません
- ページはそのまま使えます。コメント、操作 UI、シアターモード、全画面もそのままです
- 動画のダウンロード、広告の除去、データの収集・送信は一切行いません

> **注意：まだ実機の GPU で速度を測っていない試作版です。** 推論の計算結果が PyTorch 版の RIFE と一致すること（下記「検証」）は確認済みですが、どの GPU で何 fps まで出せるかは未確認です。

## 通常版との違い

| | 通常版（ブロックマッチング） | AI 版（この拡張機能） |
| --- | --- | --- |
| 動き推定 | 8px ブロックの階層探索 | RIFE v4.6（ニューラルネット） |
| 得意 | 画面全体の平行移動（パン）、軽さ | 物体の前後関係、隠れていた背景が出てくる場所、複雑な動き |
| GPU 負荷（動き推定） | 1080p で 1〜5 ms 程度（RTX 3080） | 推論 1 回あたり約 10〜40 G 積和（プリセットによる） |
| 映像の遅延 | 1 フレーム + 表示 1 フレーム | それに加えて推論の分割数 × 表示 1 フレーム |

両方を入れている場合、通常版が動いている動画では AI 版は自動で停止します。比べるときは片方をオフにしてください。

## 用意するもの

- Chromium 系のブラウザ（Vivaldi / Chrome / Edge、バージョン 116 以降）
- WebGPU が使える **単体 GPU**。アドレスバーに `vivaldi://gpu`（Chrome は `chrome://gpu`）と入力し、**WebGPU: Hardware accelerated** と出ていれば使えます。通常版より重いので、内蔵 GPU では「速度優先」でも足りない可能性が高いです
- 表示 Hz の高いモニター（120Hz 以上）だと効果が大きくなります

## インストール

1. このリポジトリの `extension` フォルダを好きな場所に置きます（使っている間は消さずに残してください）
2. アドレスバーに `vivaldi://extensions`（Chrome は `chrome://extensions`、Edge は `edge://extensions`）と入力して開きます
3. 右上の **デベロッパーモード** をオンにします
4. **「パッケージ化されていない拡張機能を読み込む」** を押し、`extension` フォルダ（`manifest.json` があるフォルダ）を選びます
5. ツールバーに出る「NuruNuru Frames AI」アイコン（紫の再生マーク）から設定を開けます

## 使い方

YouTube やニコニコ動画で動画を再生すると、AI モデルを読み込んでから自動で補間が始まります。

| ショートカット | 動作 |
| --- | --- |
| `Alt+Shift+S` | 補間の ON / OFF |
| `Alt+Shift+D` | デモ表示（左: 元映像 / 右: 補間）の切り替え |

### ポップアップの設定

| 項目 | 内容 |
| --- | --- |
| 有効 / サイト別 | 全体、または YouTube／ニコニコごとの ON / OFF |
| 目標フレームレート | ディスプレイに合わせる（既定）／ソースの 2・2.5・3 倍／固定値 |
| 画質プリセット | AI の推論解像度。速度優先（幅 512）／標準（768）／高画質（1024）。フローは推論解像度で求め、描画は元の解像度で行います |
| アーティファクトマスキング | 前後のフレームのワープ結果が食い違う場所を、単純ブレンドに寄せて破綻を目立たなくします。0 が最もシャープです |
| シーンチェンジ検出感度 | 高いほどカット切り替えを検出しやすくなります。検出されたフレーム間は補間しません |
| 音ズレ補正 / 音声オフセット | 音声を補間の遅延ぶん遅らせます（実験的） |
| デモ表示 / フロー表示 / 統計 OSD | 動作確認用 |

ポップアップの状態欄には、出力 fps、補間率、遅延、GPU 負荷（AI 推論 ms / 描画 ms）、推論の解像度と分割数が表示されます。

### ベンチマーク

ポップアップ下の「この PC の GPU でベンチマークを測る」を押すと、推論 1 回にかかる GPU 時間をプリセットごとに測るページが開きます（1080p 動画を想定）。24 / 30 / 60fps の動画で推論が GPU 時間の何 % を使うかの目安と、処理の内訳が表示されます。結果を共有してもらえると改良の参考になります。

### GPU 負荷の自動調整

GPU のタイムスタンプで推論と描画の時間を測り、補間が GPU 時間の 70% を 3 秒続けて超えると、次の順で軽くします。推論が 5 秒間 1 度も間に合わなかった場合も同じ扱いです。

1. 画質プリセットを 1 段下げる（高画質 → 標準 → 速度優先）
2. 出力フレームレートを目標の半分にする
3. 補間を止めて元の映像を表示する（ポップアップでプリセットを選び直すと再試行します）

## 動作の仕組み

1. `requestVideoFrameCallback` で動画の新しいフレームごとに WebGPU テクスチャへ取り込み、推論解像度（各辺 32 の倍数）の RGB テンソルに変換します
2. 前後 2 フレームの組ごとに、RIFE v4.6（IFNet）を中間時刻 t=0.5 で 1 回推論し、中間時刻のグリッド上で「A へのフロー f0」「B へのフロー f1」「合成マスク m」を求めます。4 段の粗密ブロック（1/8 → 1/4 → 1/2 → 1）を、3×3 畳み込み（共有メモリでタイル化）、転置畳み込み + PixelShuffle、ワープなどの WGSL カーネルで実行します
3. 推論はおよそ 50 回のディスパッチに分かれていて、表示フレームごとに「表示 1 フレームの 45% 程度」ずつ GPU に投入します。そのぶん映像を遅らせて、必要なときには推論が終わっているようにします
4. 表示の各フレームでは、中間時刻の点 q が時刻 t に `q + (1−2t)·f0`（t<0.5）または `q + (2t−1)·f1`（t>0.5）にあるとみなし、不動点反復で q を求めます。A と B をワープしてマスク m（近い側のフレームに重み付け）で合成します。t=0.5 では RIFE の出力そのものになります
5. 結果は `<video>` の直後に重ねた canvas に描きます

## 検証

`tools/` 以外の開発用スクリプトは同梱していません。開発時には次のことを確認しました（GPU なしのソフトウェア WebGPU = SwiftShader 上）。

- WGSL 版の推論結果（フローとマスク）が PyTorch 版 RIFE v4.6 と一致すること：最大誤差 0.00007 画素（256×192 と 352×224）
- t=0.5 の描画が RIFE の合成結果と一致すること：最大誤差 0.0032（8 ビットの量子化の範囲）。t=0 / 1 では元のフレームになること
- 正解の中間フレームがわかる合成映像（640×384）での PSNR（t = 0.25 / 0.5 / 0.75）

| シーン | 通常版（高画質） | AI 版 | 参考: 毎時刻 RIFE を推論 | 単純ブレンド |
| --- | --- | --- | --- | --- |
| 背景のパンのみ | **61.3 / 58.0 / 52.8** | 47.6 / 41.7 / 47.6 | 39.8 / 41.8 / 38.6 | 15.4 / 13.1 / 15.3 |
| パン + 前景の円が逆方向に移動 | 30.6 / 28.6 / 30.9 | **32.1 / 31.2 / 32.1** | 31.0 / 31.2 / 30.5 | 15.3 / 13.2 / 15.3 |

単純な平行移動だけなら通常版のほうが正確で、物体の前後関係がある場面では AI 版が上回りました。t≠0.5 の時刻を 1 回の推論から作る近似は、毎時刻 RIFE を推論する場合と同等以上でした（合成映像の動きが等速直線なので、この近似に有利な条件ではあります）。実際の動画での比較はこれからです。

## うまくいかないとき

- **補間されない**：ポップアップの状態欄に理由が出ます
- **「GPU の性能が足りないため補間を停止しました」と出る**：プリセットを「速度優先」にするか、目標フレームレートを下げてください。それでも止まる場合は通常版を使ってください
- **WebGPU が利用できません と出る**：`vivaldi://gpu` で WebGPU が無効になっていないか確認してください

## 既知の制約

- 実機の GPU での速度は未計測です
- 通常版より映像の遅延が大きくなります（推論の分割数ぶん）。音ズレ補正はこの遅延も含めて音声を遅らせます
- DRM 付きの動画は補間できません。HDR 動画は SDR として表示されます
- モデルは RIFE v4.6 の fp32 推論のみです（fp16 化や新しい RIFE への対応はこれから）

## モデルの重みを作り直すには

`extension/models/rife-v4.6.bin` は、RIFE v4.6 のチェックポイント（`flownet_v4.6.pkl`、[HolyWu/vs-rife](https://github.com/HolyWu/vs-rife) の Releases で配布）を変換したものです。

```
python3 tools/export_weights.py flownet_v4.6.pkl extension/models/rife-v4.6.bin
```

numpy だけで動きます（PyTorch は不要です）。pickle はテンソルの復元に必要なクラスだけを許可して読み込むので、ファイル中の任意のコードは実行されません。
