# NuruNuru Frames AI

YouTube とニコニコ動画を **ブラウザの中で AI（RIFE 4.25）と従来方式（ブロックマッチング）を組み合わせて** フレーム補間し、ディスプレイのリフレッシュレート（例: 144Hz / 180Hz）でぬるぬる再生する拡張機能です。
[NuruNuru Frames](https://github.com/wahahahaha1/nurunuru-frames)（ブロックマッチング版）の別版です。

- **RIFE 4.25 / 4.25 lite** の推論を WebGPU のコンピュートシェーダーで自前実装しています。onnxruntime などの外部ランタイムは使いません（同梱するのはモデルの重み 2 つ、計約 24MB だけです）
- **ハイブリッド**：従来方式の動き推定も同時に行い、そちらが前後のフレームをよく説明できる場所（パン、細かい模様）だけそちらを使います。物体の前後関係や大きな動きは RIFE に任せます
- **アニメの作画（2 コマ・3 コマ打ち）に対応**：同じ絵が続くフレームを見分けて、絵が変わったフレーム同士の間で補間します
- **フェードや明るさの変化に対応**：前後のフレームの明るさの比を求め、時刻に応じた明るさにそろえてから補間します
- 補間フレームは双三次（Catmull-Rom）でサンプリングし、元のフレームと同じ鮮明さを保ちます（補間フレームだけボケて鮮明さが脈打つのを防ぎます）
- 推論は **ソースの 2 フレーム（2 枚の絵）につき 1 回**（中間時刻 t=0.5）だけ行い、任意の時刻 t のフレームは、その結果を使って軽いシェーダーで作ります。出力が 144fps でも 180fps でも推論回数は増えません
- 1 回の推論を複数の表示フレームに分けて GPU に投入するので、推論中も画面の更新が止まりません
- ページはそのまま使えます。コメント、操作 UI、シアターモード、全画面もそのままです
- 広告の除去、データの収集・送信、動画の保存は一切行いません

> **試作版です。** 推論の計算結果が PyTorch 版の RIFE と一致すること（下記「検証」）は確認済みです。実機での速度は RTX 3080 でだけ測っています（下記「速度」）。

## 通常版との違い

| | 通常版（ブロックマッチング） | AI 版（この拡張機能） |
| --- | --- | --- |
| 動き推定 | 8px ブロックの階層探索 | RIFE 4.25（ニューラルネット）+ ブロックマッチング |
| 得意 | 画面全体の平行移動（パン）、軽さ | アニメ、大きな動き、物体の前後関係（パンはブロックマッチングの結果も使います） |
| GPU 負荷（動き推定） | 1080p で 1〜5 ms 程度（RTX 3080） | 2 枚の絵の組 1 つにつき 10〜36 ms（RTX 3080、プリセットによる） |
| 映像の遅延 | 1 フレーム + 表示 1 フレーム | 1 枚の絵の間隔 + 表示 1 フレーム + 推論の分割数 × 表示 1 フレーム |

両方を入れている場合、通常版が動いている動画では AI 版は自動で停止します。比べるときは片方をオフにしてください。

## 用意するもの

- Chromium 系のブラウザ（Vivaldi / Chrome / Edge、バージョン 116 以降）
- WebGPU が使える **単体 GPU**。アドレスバーに `vivaldi://gpu`（Chrome は `chrome://gpu`）と入力し、**WebGPU: Hardware accelerated** と出ていれば使えます。通常版より重いので、内蔵 GPU では「速度優先」でも足りない可能性が高いです
- 表示 Hz の高いモニター（120Hz 以上）だと効果が大きくなります

## ダウンロード

[Releases](../../releases) から `nurunuru-frames-ai-<バージョン>.zip` をダウンロードしてください。

## インストール

1. ダウンロードした zip を好きな場所に展開します（または、このリポジトリの `extension` フォルダを使います）。展開してできた `nurunuru-frames-ai` フォルダは、使っている間は消さずに残しておいてください
2. アドレスバーに `vivaldi://extensions`（Chrome は `chrome://extensions`、Edge は `edge://extensions`）と入力して開きます
3. 右上の **デベロッパーモード** をオンにします
4. **「パッケージ化されていない拡張機能を読み込む」** を押し、`manifest.json` があるフォルダを選びます
5. ツールバーに出る「NuruNuru Frames AI」アイコン（紫の再生マーク）から設定を開けます

## 使い方

YouTube やニコニコ動画で動画を再生すると、AI モデルを読み込んでから自動で補間が始まります。

| ショートカット | 動作 |
| --- | --- |
| `Alt+Shift+S` | 補間の ON / OFF |
| `Alt+Shift+D` | デモ表示（左: 元映像 / 右: 補間）の切り替え |

### ポップアップの設定

| 項目 | 内容 |
| --- | --- |
| 有効 / サイト別 | 全体、または YouTube／ニコニコごとの ON / OFF |
| 目標フレームレート | ディスプレイに合わせる（既定）／ソースの 2・2.5・3 倍／固定値 |
| 画質プリセット | 速度優先（RIFE 4.25 lite、幅 768）／標準（RIFE 4.25、幅 960）／高画質（RIFE 4.25、幅 1280）。動きは推論解像度で求め、描画は元の解像度で行います |
| ブロックマッチングと併用 | 従来方式の動き推定も行い、そちらがよく合う場所ではそちらを使います（既定でオン） |
| アニメの作画に合わせる | 同じ絵が続くフレームを飛ばし、絵が変わったフレーム同士の間で補間します（既定でオン）。同じ絵が続く動画では、そのぶん映像の遅延が増えます |
| 入れ替えても推論して平均 | 前後のフレームを入れ替えた組でも RIFE を動かし、2 つの結果を平均します。RIFE の推論の偏りが打ち消されて動きが正確になります（RIFE の推論 2 回、既定でオン）。GPU が足りないときは最初に自動でオフになります |
| 半分の解像度でも推論 | 縮小した映像でも RIFE を動かし、速い動きをそちらのほうがよく捉える場所で使います（処理 約 1.3〜1.4 倍、ハイブリッドがオンのとき、既定でオン）。GPU が足りないときは自動でオフになります |
| 大きな動きを高精度に | 2 枚の絵の中間（t=0.5）に加えて 1/4・3/4 の時刻でも推論し、t=0.5 からの外挿が合わない画素だけそちらを使います（推論 3 倍、既定でオフ）。GPU が足りないときは自動でオフになります |
| アーティファクトマスキング | どちらの動きも信用できない場所で、崩れた画の代わりに近いほうの元フレームを表示します。0 で無効 |
| シーンチェンジ検出感度 | 高いほどカット切り替えを検出しやすくなります。検出されたフレーム間は補間しません |
| 演出を優先（補間しない場面） | 一瞬の大きな動き（ツメ・スミア）、画面の揺れ、フラッシュを検出し、その組は補間せず元の動画のタイミングで表示します。急な変化そのものが見せ方になっている場面で、なめらかにして勢いが弱まるのを防ぎます。種類ごとにオン／オフ（既定はすべてオフ）、検出の感度を設定できます。動きの大きさは前の組と比べるので、一定の速さのパンは対象外です |
| GPU 負荷の上限 | 補間の処理がこの割合を超える状態が 3 秒続くと、重い処理を順に自動でオフにします。自動（処理落ちがあるときは 70%、ないときは 90%）／50〜100%／自動で軽くしない（推論がまったく終わらないときだけ止めます） |
| 先読み（バッファ） | 映像をさらに 0.1〜0.5 秒遅らせ、一瞬の処理落ちを吸収します（既定はなし）。動画のフレームはブラウザが再生した時点で届くため、それより先は読めません。GPU のメモリを余分に使います |
| 音ズレ補正 / 音声オフセット | 音声を補間の遅延ぶん遅らせます（実験的）。遅延を変えるときは 2 本の遅延の間をクロスフェードするので、音程は変わりません。遅延は直近 10 秒の映像の遅延の最大に合わせ、変える回数を抑えます |
| デモ表示 / フロー表示 / 統計 OSD | 動作確認用 |

ポップアップの状態欄には、出力 fps、補間率、遅延、GPU 負荷（推論 ms / 描画 ms）、推論の解像度と分割数が表示されます。

### 速度

RTX 3080 で、ポップアップの「この PC の GPU でベンチマークを測る」を使って測った値です。「処理 1 回」は 2 枚の絵の組 1 つにかかる時間（RIFE の推論、ブロックマッチング、選択など既定の設定すべて）で、その右は、1 秒あたりに新しい絵がその枚数来たときの GPU 負荷です。

| プリセット | 推論の解像度 | 積和 | 処理 1 回 | 12 枚/秒 | 24 枚/秒 | 30 枚/秒 | 60 枚/秒 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 速度優先 | RIFE 4.25 lite 768×432 | 約 7.4 G | 10.2 ms | 12% | 25% | 31% | 61% |
| 標準 | RIFE 4.25 960×544 | 約 23.6 G | 15.9 ms | 19% | 38% | 48% | 95% |
| 高画質 | RIFE 4.25 1280×720 | 約 40.8 G | 36.3 ms | 44% | 87% | 109% | 218% |

推論は絵の組ごとに 1 回なので、負荷は出力の fps ではなく、元の動画の 1 秒あたりの絵の枚数で決まります。表示 1 フレームの描画は 0.07 ms です。高画質は測るたびに 24〜42 ms とばらつきがありました（表は中央値）。

設定ごとの処理 1 回の時間（標準）：

| 設定 | 処理 1 回 | 30 枚/秒 |
| --- | ---: | ---: |
| 既定の設定 | 15.9 ms | 48% |
| ＋ 左右反転でも推論（推論 4 回） | 26.4 ms | 79% |
| ＋ 大きな動きを高精度に（推論 3 回） | 27.8 ms | 83% |
| 入れ替えての推論なし | 10.9 ms | 33% |
| 半分の解像度での推論なし | 12.6 ms | 38% |
| ハイブリッドなし（RIFE のみ） | 6.3 ms | 19% |

### 検証

`tools/` 以外の開発用スクリプトは同梱していません。開発時には次のことを確認しました（GPU なしのソフトウェア WebGPU = SwiftShader 上）。

- WGSL 版の推論結果（フローとマスク）が PyTorch 版 RIFE 4.25 / 4.25 lite と一致すること：最大誤差 0.00007 画素（パディングが必要なサイズ、t=0.25 の推論を含む）
- t=0.5 の描画が RIFE の合成結果と一致すること：最大誤差 0.003（8 ビットの量子化の範囲）。t=0 / 1 では元のフレームになること
- アニメの作画への対応：重複フレームの判定（圧縮ノイズ ±2 階調は「重複」、40×40 画素だけの変化は「別の絵」）、絵の組の作り方、2 コマ打ち・3 コマ打ち・通常の動画・長い静止での絵の組と時刻の選び方

ハイブリッドは、ほとんどの場面で「従来版と AI のみの良いほう」と同等以上です。AI（元の解像度・半分の解像度）と従来方式のどれを使うかは、合成映像と写真を動かした映像の 28 種類で「どの場面も悪くせずに平均の PSNR が最も高くなる」ように当てはめたモデルで、画素ごとに決めています。1 フレームに画面幅の 17% 動く極端に速い物体（高速移動）は、半分の解像度での推論でかなり改善しました。残る弱点は急に迫ってくるキャラクター（アニメ 2）で、RIFE 単体でもうまく推論できない場面です。合成映像には限界があるので、利用が許されている実際の動画（自由なライセンスのものなど）での比較も進めていきます。

### 実写（写真を動かした映像）での画質

本物の写真（scikit-image に同梱のサンプル画像）を、カメラのように動かした映像 6 種類です。シャッター角 180° のモーションブラー、センサーノイズ、4:2:0 と JPEG の圧縮を加えてあります。ステレオ写真は、実測の視差を使って横に動くカメラの映像にしたもので、奥行きによって動きの量が 7 倍ほど違い、物体の前後の重なりも実物どおりです。「ハイブリッド」は既定の設定（入れ替えても推論して平均、半分の解像度でも推論）での値です。

| 場面 | 単純ブレンド | 従来版 | AI のみ | ハイブリッド |
|---|---:|---:|---:|---:|
| ステレオ写真の横移動（奥行きで動きが違う） | 22.2 | 32.6 | 32.7 | **33.2** |
| 人物写真のズーム | 25.4 | 40.8 | 40.4 | **40.8** |
| 猫の写真、手持ちカメラ（パンと回転） | 29.5 | 41.0 | 41.1 | **41.5** |
| コーヒーの写真、カメラの回転 | 27.9 | 36.9 | 38.3 | **38.9** |
| 草が風で揺れる（形の変わる動き） | 27.2 | 29.6 | **30.1** | 30.1 |
| 星空のパン、360p 相当の強い圧縮 | 26.2 | 33.5 | 35.4 | **35.6** |

ハイブリッドは 6 種類中 5 種類で最も正確で、草が風で揺れる場面も AI のみとほぼ同じです（形の変わる動きは、選択のモデルの弱点として残っています）。ゆるやかなカメラの動きでは、従来版との差は小さめです。人が歩くといった実写特有の動きや、速い動きの実写は、まだ検証できていません。

苦手な動きの一覧と対策の状況は [docs/weaknesses.md](docs/weaknesses.md) にまとめています。

## うまくいかないとき

- **補間されない**：ポップアップの状態欄に理由が出ます
- **「GPU の性能が足りないため補間を停止しました」と出る**：プリセットを「速度優先」にするか、目標フレームレートを下げてください。「半分の解像度でも推論」や「ブロックマッチングと併用」をオフにすると軽くなります。設定を変えるか次の動画に移ると、再び補間を試みます
- **WebGPU が利用できません と出る**：`vivaldi://gpu` で WebGPU が無効になっていないか確認してください
- **映像と音がずれる**：AI 版は通常版より映像の遅延が大きくなります。「音ズレ補正」をオンにしてください

## 既知の制約

- 通常版より映像の遅延が大きくなります（推論の分割数ぶん。アニメの作画に合わせる設定では、同じ絵が続くぶんも）
- DRM 付きの動画は補間できません。HDR 動画は SDR として表示されます
- 推論は fp32 のみです

## モデルの重みを作り直すには

`extension/models/` の重みは、RIFE 4.25 / 4.25 lite のチェックポイント（`flownet_v4.25.pkl` / `flownet_v4.25.lite.pkl`、[HolyWu/vs-rife](https://github.com/HolyWu/vs-rife) の Releases で配布）を fp16 に変換したものです。

```
python3 tools/export_weights.py flownet_v4.25.pkl rife-4.25 extension/models/rife-v4.25.bin
python3 tools/export_weights.py flownet_v4.25.lite.pkl rife-4.25-lite extension/models/rife-v4.25-lite.bin
```

numpy だけで動きます（PyTorch は不要です）。pickle はテンソルの復元に必要なクラスだけを許可して読み込むので、ファイル中の任意のコードは実行されません。
