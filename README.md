# NuruNuru Frames AI

YouTube とニコニコ動画を **ブラウザの中で AI（RIFE 4.25）と従来方式（ブロックマッチング）を組み合わせて** フレーム補間し、ディスプレイのリフレッシュレート（例: 144Hz / 180Hz）でぬるぬる再生する拡張機能です。
[NuruNuru Frames](https://github.com/wahahahaha1/nurunuru-frames)（ブロックマッチング版）の別版です。

- **RIFE 4.25 / 4.25 lite** の推論を WebGPU のコンピュートシェーダーで自前実装しています。onnxruntime などの外部ランタイムは使いません（同梱するのはモデルの重み 2 つ、計約 24MB だけです）
- **ハイブリッド**：従来方式の動き推定も同時に行い、そちらが前後のフレームをよく説明できる場所（パン、細かい模様）だけそちらを使います。物体の前後関係や大きな動きは RIFE に任せます
- **アニメの作画（2 コマ・3 コマ打ち）に対応**：同じ絵が続くフレームを見分けて、絵が変わったフレーム同士の間で補間します
- 推論は **ソースの 2 フレーム（2 枚の絵）につき 1 回**（中間時刻 t=0.5）だけ行い、任意の時刻 t のフレームは、その結果を使って軽いシェーダーで作ります。出力が 144fps でも 180fps でも推論回数は増えません
- 1 回の推論を複数の表示フレームに分けて GPU に投入するので、推論中も画面の更新が止まりません
- ページはそのまま使えます。コメント、操作 UI、シアターモード、全画面もそのままです
- 広告の除去、データの収集・送信は一切行いません。動画の保存は、検証用の記録ボタンを押したときに数秒分を手元に保存するだけです

> **試作版です。** 推論の計算結果が PyTorch 版の RIFE と一致すること（下記「検証」）は確認済みです。実機では RTX 3080 で RIFE 4.6 版の推論時間を測りました（推論 1 回 11〜15ms）。4.25 版の実機での速度はまだ測っていません。

## 通常版との違い

| | 通常版（ブロックマッチング） | AI 版（この拡張機能） |
| --- | --- | --- |
| 動き推定 | 8px ブロックの階層探索 | RIFE 4.25（ニューラルネット）+ ブロックマッチング |
| 得意 | 画面全体の平行移動（パン）、軽さ | アニメ、大きな動き、物体の前後関係（パンはブロックマッチングの結果も使います） |
| GPU 負荷（動き推定） | 1080p で 1〜5 ms 程度（RTX 3080） | 推論 1 回あたり数 G〜十数 G 積和（プリセットによる）+ ブロックマッチング |
| 映像の遅延 | 1 フレーム + 表示 1 フレーム | 1 枚の絵の間隔 + 表示 1 フレーム + 推論の分割数 × 表示 1 フレーム |

両方を入れている場合、通常版が動いている動画では AI 版は自動で停止します。比べるときは片方をオフにしてください。

## 用意するもの

- Chromium 系のブラウザ（Vivaldi / Chrome / Edge、バージョン 116 以降）
- WebGPU が使える **単体 GPU**。アドレスバーに `vivaldi://gpu`（Chrome は `chrome://gpu`）と入力し、**WebGPU: Hardware accelerated** と出ていれば使えます。通常版より重いので、内蔵 GPU では「速度優先」でも足りない可能性が高いです
- 表示 Hz の高いモニター（120Hz 以上）だと効果が大きくなります

## インストール

1. ダウンロードした zip を好きな場所に展開します（または、このリポジトリの `extension` フォルダを使います）。展開してできた `nurunuru-frames-ai` フォルダは、使っている間は消さずに残しておいてください
2. アドレスバーに `vivaldi://extensions`（Chrome は `chrome://extensions`、Edge は `edge://extensions`）と入力して開きます
3. 右上の **デベロッパーモード** をオンにします
4. **「パッケージ化されていない拡張機能を読み込む」** を押し、`manifest.json` があるフォルダを選びます
5. ツールバーに出る「NuruNuru Frames AI」アイコン（紫の再生マーク）から設定を開けます

## 使い方

YouTube やニコニコ動画で動画を再生すると、AI モデルを読み込んでから自動で補間が始まります。

| ショートカット | 動作 |
| --- | --- |
| `Alt+Shift+S` | 補間の ON / OFF |
| `Alt+Shift+D` | デモ表示（左: 元映像 / 右: 補間）の切り替え |

### ポップアップの設定

| 項目 | 内容 |
| --- | --- |
| 有効 / サイト別 | 全体、または YouTube／ニコニコごとの ON / OFF |
| 目標フレームレート | ディスプレイに合わせる（既定）／ソースの 2・2.5・3 倍／固定値 |
| 画質プリセット | 速度優先（RIFE 4.25 lite、幅 768）／標準（RIFE 4.25、幅 960）／高画質（RIFE 4.25、幅 1280）。動きは推論解像度で求め、描画は元の解像度で行います |
| ブロックマッチングと併用 | 従来方式の動き推定も行い、そちらがよく合う場所ではそちらを使います（既定でオン） |
| アニメの作画に合わせる | 同じ絵が続くフレームを飛ばし、絵が変わったフレーム同士の間で補間します（既定でオン）。同じ絵が続く動画では、そのぶん映像の遅延が増えます |
| アーティファクトマスキング | どちらの動きも信用できない場所で、崩れた画の代わりに近いほうの元フレームを表示します。0 で無効 |
| シーンチェンジ検出感度 | 高いほどカット切り替えを検出しやすくなります。検出されたフレーム間は補間しません |
| 音ズレ補正 / 音声オフセット | 音声を補間の遅延ぶん遅らせます（実験的） |
| デモ表示 / フロー表示 / 統計 OSD | 動作確認用 |

ポップアップの状態欄には、出力 fps、補間率、遅延、GPU 負荷（推論 ms / 描画 ms）、推論の解像度と分割数が表示されます。

### 検証用の記録

ポップアップの「3 秒記録」を押すと、これから 3 秒分の **元の動画フレーム**（最大幅 1280 の PNG 連番と、各フレームの時刻などを書いた `meta.json` を zip にしたもの）と、**補間後の映像**（WebM）をダウンロードフォルダに保存します。うまく補間できない場面の報告や、補間の品質の検証（1 枚おきにフレームを抜いて補間し、抜いたフレームと比べる）に使います。保存先はこの PC だけで、どこにも送信しません。

### ベンチマーク

ポップアップ下の「この PC の GPU でベンチマークを測る」を押すと、推論 1 回にかかる GPU 時間をプリセットごとに測るページが開きます（1080p 動画を想定）。24 / 30 / 60fps の動画で推論が GPU 時間の何 % を使うかの目安と、処理の内訳が表示されます。

### GPU 負荷の自動調整

推論の各ステップと描画の GPU 時間をタイムスタンプで測り、補間が GPU 時間の 70% を 3 秒続けて超えると、次の順で軽くします。推論が 5 秒間 1 度も間に合わなかった場合も同じ扱いです。

1. 画質プリセットを 1 段下げる（高画質 → 標準 → 速度優先）
2. 出力フレームレートを目標の半分にする
3. 補間を止めて元の映像を表示する（ポップアップでプリセットを選び直すと再試行します）

## 動作の仕組み

1. `requestVideoFrameCallback` で動画の新しいフレームごとに WebGPU テクスチャへ取り込み、推論用の RGB テンソル（モデルの要求に合わせて 64 / 128 の倍数までゼロでパディング）と、ブロックマッチング用の輝度ピラミッドを作ります
2. アニメの作画に合わせる設定では、前のフレームと 8×8 ブロック単位で比べ、変化したブロックが 1 つもなければ「同じ絵の繰り返し」とみなします（画面全体の平均ではなくブロック単位なので、口だけが動くような小さな変化も見逃しません）
3. 絵が変わったフレームの組ごとに、RIFE 4.25（IFNet）を中間時刻 t=0.5 で 1 回推論し、中間時刻のグリッド上で「A へのフロー f0」「B へのフロー f1」「合成マスク m」を求めます。各フレームの特徴抽出（Head）と 5 段の粗密ブロックを、3×3 畳み込み（共有メモリでタイル化、小さい層は入力チャンネル分割）、転置畳み込み + PixelShuffle、ワープなどの WGSL カーネルで実行します
4. 同じジョブの中でブロックマッチング（前後方向、時間予測、サブピクセル、メディアン）も行い、両方式が前後のフレームをどれだけ説明できるかを比べた **選択マップ** を作ります。RIFE のマスクが片側のフレームだけを選んでいる場所（オクルージョン）は RIFE に任せます
5. 推論はおよそ 120 回のディスパッチに分かれていて、実測した各ステップの GPU 時間をもとに、表示フレームごとに「表示 1 フレームの 45% 程度」ずつ GPU に投入します。そのぶん映像を遅らせて、必要なときには推論が終わっているようにします
6. 表示の各フレームでは、中間時刻の点 q が時刻 t に `q + (1−2t)·f0`（t<0.5）または `q + (2t−1)·f1`（t>0.5）にあるとみなし、不動点反復で q を求めます。A と B をワープしてマスク m（近い側のフレームに重み付け）で合成します（t=0.5 では RIFE の出力そのもの）。選択マップがブロックマッチングを選んでいる場所では、そちらの補間結果を使います
7. 結果は `<video>` の直後に重ねた canvas に描きます

## 検証

`tools/` 以外の開発用スクリプトは同梱していません。開発時には次のことを確認しました（GPU なしのソフトウェア WebGPU = SwiftShader 上）。

- WGSL 版の推論結果（フローとマスク）が PyTorch 版 RIFE 4.25 / 4.25 lite と一致すること：最大誤差 0.00007 画素（パディングが必要なサイズを含む）
- t=0.5 の描画が RIFE の合成結果と一致すること：最大誤差 0.003（8 ビットの量子化の範囲）。t=0 / 1 では元のフレームになること
- アニメの作画への対応：2 コマ打ち・3 コマ打ち・通常の動画・長い静止で、正しい絵の組と時刻を選ぶこと

## うまくいかないとき

- **補間されない**：ポップアップの状態欄に理由が出ます
- **「GPU の性能が足りないため補間を停止しました」と出る**：プリセットを「速度優先」にするか、目標フレームレートを下げてください。「ブロックマッチングと併用」をオフにすると少し軽くなります
- **WebGPU が利用できません と出る**：`vivaldi://gpu` で WebGPU が無効になっていないか確認してください
- **映像と音がずれる**：AI 版は通常版より映像の遅延が大きくなります。「音ズレ補正」をオンにしてください

## 既知の制約

- 通常版より映像の遅延が大きくなります（推論の分割数ぶん。アニメの作画に合わせる設定では、同じ絵が続くぶんも）
- DRM 付きの動画は補間できません。HDR 動画は SDR として表示されます
- 推論は fp32 のみです

## モデルの重みを作り直すには

`extension/models/` の重みは、RIFE 4.25 / 4.25 lite のチェックポイント（`flownet_v4.25.pkl` / `flownet_v4.25.lite.pkl`、[HolyWu/vs-rife](https://github.com/HolyWu/vs-rife) の Releases で配布）を fp16 に変換したものです。

```
python3 tools/export_weights.py flownet_v4.25.pkl rife-4.25 extension/models/rife-v4.25.bin
python3 tools/export_weights.py flownet_v4.25.lite.pkl rife-4.25-lite extension/models/rife-v4.25-lite.bin
```

numpy だけで動きます（PyTorch は不要です）。pickle はテンソルの復元に必要なクラスだけを許可して読み込むので、ファイル中の任意のコードは実行されません。
